\section{Componentes}

\subsection{Backend --- Node.js}

El backend se desarrollar\'a utilizando Node.js y expondr\'a una API REST
encargada de centralizar la l\'ogica de negocio, la autenticaci\'on, los permisos
por m\'odulo, las suscripciones y la comunicaci\'on entre el frontend, la base de
datos y los servicios de procesamiento. Tambi\'en ofrecer\'a una API
institucional autenticada.

\subsection{M\'odulo de procesamiento de datos --- Python}

El procesamiento de datos se implementar\'a en Python, utilizando principalmente
Pandas y \emph{jobs} programados. Esta capa obtendr\'a informaci\'on desde API,
Excel, CSV, PDF, HTML o JSON; validar\'a su contenido, normalizar\'a variables,
unidades y fechas, y enviar\'a los registros inconsistentes a cuarentena antes de
publicarlos.

\subsection{M\'odulo de inteligencia --- Python}

La capa de inteligencia se implementar\'a en Python mediante un motor
determin\'istico de m\'etricas y un grafo de dependencias para los cruces entre
m\'odulos. Calcular\'a cambios, momentum, divergencias regionales, percentiles
hist\'oricos, sorpresas, persistencia y distancia frente a metas.

\subsection{Frontend --- React}

El frontend ser\'a desarrollado con React y utilizar\'a componentes reutilizables
para construir \emph{dashboards}, comparadores, fichas por pa\'is, alertas,
\emph{briefings} y paneles administrativos. La interfaz adaptar\'a las
funcionalidades visibles seg\'un los permisos y m\'odulos contratados.

\section{Arquitectura de datos}

\subsection{Patr\'on Medallion}

La informaci\'on se organizar\'a mediante el patr\'on Medallion:

\begin{itemize}
  \item \textbf{Bronze:} conservar\'a archivos y respuestas originales e
        inmutables.
  \item \textbf{Silver:} almacenar\'a datos validados, normalizados y trazables.
  \item \textbf{Gold:} contendr\'a m\'etricas, cruces y se\~nales preparadas para
        \emph{dashboards}, alertas, \emph{briefings}, exportaciones y APIs.
  \item \textbf{Cuarentena:} recibir\'a los registros dudosos antes de que puedan
        publicarse.
\end{itemize}

\subsection{Base de datos --- PostgreSQL}

PostgreSQL almacenar\'a datos normalizados, m\'etricas, hist\'oricos, revisiones,
usuarios, organizaciones, permisos y registros de auditor\'ia. Los archivos
originales de la capa Bronze se conservar\'an por separado en almacenamiento de
objetos.

\subsection{Almacenamiento de objetos --- Azure Blob Storage}

Azure Blob Storage almacenar\'a los archivos originales, documentos hist\'oricos,
datos en cuarentena y exportaciones, permitiendo conservar una copia verificable
de cada fuente sin sobrecargar la base de datos principal.

\section{Uso de modelos de lenguaje}

\subsection{Extractor estructurado}

Para resolver la heterogeneidad de formatos entre fuentes, se incorpora un
componente LLM como extractor estructurado: recibe el HTML o archivo publicado
por el banco central, lo limpia y devuelve un JSON normalizado con las
expectativas en el formato interno de \proyectoNombre{}, independientemente de
c\'omo cada banco central publique su informaci\'on.

\subsection{Generaci\'on del resumen del radar}

Una vez calculadas las m\'etricas, un componente LLM recibe esos resultados ya
procesados y genera autom\'aticamente el resumen descriptivo del radar de
expectativas.

\section{Infraestructura y despliegue}

\subsection{Azure Container Apps}

La infraestructura estar\'a basada en contenedores Docker, desplegados mediante
Azure Container Apps, permitiendo desacoplar los distintos componentes del
sistema y facilitar tanto el despliegue como la escalabilidad.

\subsection{Integraci\'on y despliegue continuo}

Se incorporar\'a un proceso de Integraci\'on y Despliegue Continuo (CI/CD)
mediante GitHub Actions.

\subsection{Control de versiones}

El proyecto utilizar\'a GitHub como sistema de control de versiones y
colaboraci\'on, permitiendo administrar el c\'odigo fuente, gestionar
incidencias, realizar revisiones de c\'odigo y mantener un historial completo de
los cambios realizados durante el desarrollo.
